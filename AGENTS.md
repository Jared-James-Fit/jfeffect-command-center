- A client's default weight unit is `clients.preferred_weight_unit` (NOT NULL, lb default); `weight_unit_confirmed_at` marks that they actually chose it, and every client-side unit save goes through `saveWeightUnitChoice` (weight-unit-pref.ts), which stamps it — why: lb can't tell "chose pounds" from "never asked", and the "Pounds or kilograms?" prompt keeps asking each app open until it's stamped.
- RLS policies check the signed-in user once per query, never per row: wrap user-only helpers as `(SELECT has_role((SELECT auth.uid()), 'admin'))` / `(SELECT auth.uid())`, and use set lookups (`client_id IN (SELECT coached_client_ids())`, `block_id IN (SELECT client_visible_pl_block_ids())`) instead of per-row `is_assigned_coach(...)` or multi-table `EXISTS`. A migration that adds policies can end with `SELECT public.rls_evaluate_once('<table>');` (idempotent, same access) — why: bare per-row checks made a client's workout block take ~540ms instead of ~20ms, across every table.
- Double-tapping a message likes it, Instagram style, in the coach chat and the group / 1:1 chats alike (`onDoubleTapLike` → `doubleTapAdds`, message-like.ts): it leaves your reaction as the default (`app_settings.chat_default_reaction`, ❤️ unless the coach picks another in Chat Settings; `DEFAULT_REACTION` when unset), adding it or switching yours to it, and never takes it back (tapping the heart under the message removes it); each double-tap springs the heart in (`animate-like-pop`). ❤️ leads every reaction bar — why: a double-tap that toggled meant a quick second double-tap silently unliked, and a ✅ read like a task tick, not a like.
